# Browse dated Wiki revisions in the Web workbench

Development-source capability, not yet published to npm. Open the existing local console and choose **知识合并** (Merge review). No new route, credential, configuration or browser storage is needed.

1. Choose an authorized compiled page. **按完整提交编号** remains the default and accepts the previous full local hash. Choose **按 Git 记录时间** to enter an ISO timestamp such as `2026-01-15T12:00:00+08:00` or `2026-01-15T04:00:00Z`. An explicit timezone and at most three fractional-second digits are required. The existing server validates the exact date; the browser does not guess local midnight, normalize an invalid day or silently substitute another version. Only the active selector is submitted.
2. Read the complete historical/current comparison. Date mode shows the normalized requested UTC time, selected committer timestamp, actual full historical hash and first-parent traversal count. Read the warning and expandable server restrictions. Selection uses mutable Git committer clocks along the current HEAD first-parent chain, not fact validity or what an agent knew. The same date may select differently after history changes; copy the actual hash if repeatability matters. Missing, oversized, expired, withdrawn, erased or unauthorized content is refused, not replaced with today's text.
3. If authorized to write, edit and prepare a proposal. Preparation uses **the hash already returned by this read**; it never resolves the date again. The current comparison is separately read using the original response's authority hash, with existing current-head/revision checks. The date-resolution notice stays with this read through proposal preparation. It is not part of a signed grant or proof that the prose is true. Inspect the complete signed proposal and separately confirm approval as described in [Web manual merge](web-manual-merge.md).

Changing mode, date, selected page or confidential flags cancels the owned read and invalidates comparisons, resolved-time metadata and old approval/retry controls. An unsaved draft remains visible for copying, but cannot be prepared against the new selection until versions are reloaded. Reloading asks before replacing that draft. Draft edits invalidate the proposal, not the existing version selection. Both new controls are disabled during approval. An uncertain save may be retried only by explicitly choosing the retained original signed plan, without a new date lookup or automatic retry.

Leaving or disconnecting cancels owned work and clears date, body and plan from the page. Authorized text is plaintext once displayed and cannot be recalled after copying. The [recorded-time reader's restrictions](dated-wiki-views.md), current access checks, private-content opt-in, complete-text transport limits and separate read/write/review permissions remain unchanged. No model request or canonical write happens during date browsing or preparation. No historical answering, public sharing, cross-vault merge, automatic approval, publication or deployment is added.

No database, data, vault-format, dependency or configuration migration.
