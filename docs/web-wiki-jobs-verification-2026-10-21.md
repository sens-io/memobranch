## 本轮交付

- 管理界面增加“编译任务”：提交已有证据、查看实际阶段、筛选、明确执行一次、取消、重新排队、删除，以及来源与修改前后比较。
- 仅提交和重试不调用模型。执行请求被接收不等于执行成功；保存的任务状态才是检查依据。每个 Web 服务实例最多拥有一次执行，没有后台调度、自动启动或自动重试。
- 接收后不因浏览器断开而取消；正常关闭 Web 服务会取消并等待它自己启动的任务，不影响独立命令行执行。强制终止沿用死进程检测和明确重试。
- 新增 `wikiReviewJob(id)`，在同一次加锁读取中返回计划和比较。网页批准必须提交刚才显示的签名；`wikiApplyJob(id, expectedProof)` 的可选第二参数让库使用者也能拒绝被重试替换的计划。
- 原身份、租户、权限、证据限制、加密、删除与恢复检查继续有效。公开输入也需要现有主密钥；浏览器不接受凭据、身份或范围配置。
- 界面延续 Logo 对应的蓝、紫、青配色。隐藏、离页与断开连接停止刷新；一次只读取一份状态。未变化的行不因其他任务更新而被移除。

用法和 HTTP 操作说明见 [任务指南](wiki-jobs.md)。任务状态记录编译，不是审核账本；应用后显示本次提交，刷新后检查 Git 历史或正式页面，不将 `ready` 当作已应用。

### 依赖审计的证据范围

初次记录 `.scratch/web-jobs-audit.json` 按包聚合为 1 个 high，包含 2 条高危与 1 条中危公告。上游官方的 [HTTP 共享实例串线公告](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-jm63-cq47-j5jp)、[HTTP 输入校验资源耗尽公告](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-46jr-4wx8-v453)及[令牌目标服务检查公告](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-rvq5-wwqv-78pq)均列出 server 2.3.0 修复版。

本项目 MCP 入口只使用 `serveStdio`，网页服务不使用 SDK 的 HTTP 传输或令牌验证。这些代码不处于公告列明的 HTTP 使用方式；不能据审计列表声称网页已发生串线或越权，也不能声称升级会自动启用未使用的 HTTP 防护选项。升级最低依赖是为了不再安装已知受影响版本。锁文件仅修改 server/core；它们的包声明许可证由 MIT 变为 Apache-2.0，实际安装保留完整上游 LICENSE，含过渡说明及两份许可证文本，不将历史贡献一概解释为已转为 Apache-2.0。本项目自身 MIT 文件未改。更新后审计留在 `.scratch/web-jobs-mcp-audit.json`，真实 MCP 定向检查留在 `.scratch/web-jobs-mcp-targeted.log`。

开发过程中，初次新增 HTTP 检查有 3/6 失败：测试把带来源链接的正式比较正文误认为与原始草稿相同，且受限测试身份漏填租户。修正测试资料和预期后，原 HTTP 用例全部通过；生产权限检查没有放宽，比较继续核对完整返回值和来源页面。最初记录留在 `.scratch/web-jobs-http.log`。这与独立审查发现的运行交互问题不同，不将测试资料错误当作产品修复。

## 限制与交付状态

- 单机、单提交身份的既有任务规则不变；不支持跨机执行、调度、自动清理、PDF、抓取、自动批准或后台服务安装。
- 取消任务不撤回独立保存的计划或已选取授权的应用操作。申请结果未知时先查状态／历史，不能盲目重新提交、执行或批准。
- 任务列表只暴露元数据；明确审核返回可能敏感的正文。正常退出是取消后等待清理，突然进程退出与断电不是同一保证。
- 两个 Node 版本的安装测试必须实际从消费者 `node_modules/memobranch` 运行；没有用源码加载器冒充最低版本验收。

数据库变更：无。数据迁移：无。配置变更：无新配置格式或凭据字段；任务仍需已有 `AMEM_MASTER_KEY` 和模型配置，网页不能保存它们。依赖变更：MCP server 最低要求 `^2.3.0`，锁定 server/core 2.3.0；已有源码 checkout 更新后需要 `npm ci`，本机验证环境已更新，不能据此称用户部署已更新。没有更改真实凭据或资料库。
