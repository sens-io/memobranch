## 本批实现

- 普通已批准记忆增加可选的 `validFrom`、`validUntil`，分别表示包含起点、不包含终点的事实生效区间。保存时间不充当事实生效时间，缺失端点明确表示未知。
- 审核者通过 `setMemoryValidity`（修改时间标注的接口）提交两个可空端点及 `expectedRevision`（刚读取的版本）。同一写入锁内检查版本、权限与证据；不改变正文、原始证据、创建或验证时间，也不恢复撤销状态。无变化不增加版本。
- `memoriesAt`（按指定日期读取现存记忆的接口）保留当前权限、租户、证据访问、到期、撤销和删除限制，并先过滤再统计与分页。保留的旧替代记录、冲突记录只能带明确提示返回，不被当作当前事实。
- 当前检索、完整记录读取、常驻上下文及依赖普通记忆的 Wiki 页面检查生效区间。旧索引不能绕过日期限制；派生搜索缓存由版本 5 升至 6，自动重建。
- 命令行提供 `memory validity` 与 `memory at`；MCP 和 Harness 提供只读 `memory_at`；HTTP 提供带确认的修改和只读查询。网页日期控件不在本批范围内。
- 模型请求前及重试前重新检查；普通问答返回后再次检查。整批读取使用原有写锁，同一读取内部复用真实有效的读取上下文，无关请求不能借用它。批内后续读取或释放锁期间跨过终点，也会拒绝发送。

用法、日期格式、未知时间与版本兼容说明见[有效时间指南](effective-time.md)。没有自动提取日期、拆分区间、安排未来替代、恢复历史 Git 状态或生成历史 Wiki 答案。

## 限制与交付状态

- 指定日期查询使用最新保留版本和最新审核标注，不是“当时系统知道什么”，不恢复旧权限、旧密钥或已删除资料。没有全量历史 Wiki 重建。
- 缺失日期不自动推测；完全无日期的记录默认不进入日期查询。当前查询仍按原规则使用未标日期的记忆。
- 现有整条替代规则没有改成未来定时切换；不自动关闭、拆分或修正其他记录的区间，也不自动解决冲突。
- `MEMORY.md` 等生成文件是最后一次写入时的内容，时间流逝不会自动刷新 Git 文件；需要当前状态时使用当前查询接口。
- 请求检查保证参与原写锁机制的读取在作出请求决定时一致，不保证决定之后正式记录永不变化，也不能撤回已发请求。新增检查不单独把锁延长到等待模型响应；已有外层完整读取保持原生命周期。
- 内置请求等待受取消和期限限制；任意自定义回调启动的工作不一定可被终止，同步阻塞也不能被事件循环计时器中断。自定义传输实现必须遵守每次发送前的检查回调。
- 旧版本不会执行这些时间限制。使用新标注前应停止旧进程，不能混用旧读写者；不能把清空标注当作无风险降级操作。
- 验证只使用临时合成资料、受控模型响应及测试服务，没有调用真实外部模型来证明回答质量，没有访问或修改用户真实资料库。本批没有界面布局改动，也没有将截图当作日期控件验收。
