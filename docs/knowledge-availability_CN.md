# 明确记录知识何时可用（开发源码）

目前是库接口核心候选，命令行、Agent 工具和网页入口尚未实现。它与按 Git 日期查看
版本、按事实生效时间筛选不同；不表示已发布 npm，也不证明真实模型何时理解了知识。

```ts
const recorded = await vault.wikiObserveAvailability({
  pageKeys: ['concept:deployment'], confirm: true,
});
const view = await vault.wikiAsKnownAt({
  pageKeys: ['concept:deployment'], at: recorded.observedAt,
});
```

记录需要读取、写入权限及明确确认。从当前干净 HEAD 读取指定页面，将精确版本、
来源和规则摘要签名后保存为不可变证据，不批准、修改或执行知识内容。不同非公开
作用域要分开记录，敏感等级不能低于来源；敏感／机密资料须明确设置
`includeSensitive` / `includeSecret`，未选中时不解密。保存前会重新检查来源、配置、
HEAD、所属身份和权限，异步检查后还会在最终保存决定前再次同步检查。

`observedAt` 来自宿主本机时钟，不取 Git 提交日期。本机时钟和证明密钥是受信任的
运行条件，并非独立时间认证。记录一个已有页面，不能证明它首次何时可用，更不能
证明 Agent 已读取、理解或相信其中的事实。这里只保留部分明确观察；旧历史、伪造
标记或无法验证的记录会显示未知，丢失证明密钥不会自动重建信任。

查询为每个名称选取不晚于 `at` 的最新可验证记录。同一时刻存在不同内容时显示未知，
不会按文件名选一个。结果说明 `coverage.mode`（本次查找范围），逐项返回 `observed`
或 `unknown`，只有前者包含精确提交内容。查询不调用模型、不新增记录、不写回正式
知识，也不是对未来的建议。

历史读取仍受当前所属身份、操作／资料权限、来源完整性、解密密钥、撤回和到期限制。
选定旧版本不可读时不会退回更旧内容绕过限制，不恢复已擦除的密钥。精确历史页面、
来源与规则摘要由现有本机快照读取检查；本机证明密钥不进入 Git，不作为共享密钥导出。
已复制的明文不能撤回。
生效的内置规则实现也记录摘要，实现变化时不能冒充与观察时一致。
每个名称只绑定自身的完整依赖，无关页面、请求顺序或其他页面的内置规则不能制造冲突。
读取使用持锁期间的一致内容；已开始的查询若与稍后的撤回重叠，可能返回该次读取的版本，
撤回后发起的新查询必须遵守撤回结果。这不表示能够追回已经读出或复制的明文。

限制：1–25 个名称，沿用快照依赖限制；清单最多 200 个文档、160,000 字符；完整查询
结果最多 20 MB。默认扫描最多 2,000 条当前可读、明确选择的原始证据或 20 MB，超限
报错，不截断。也可提供 1–40 个不重复的 `observationIds` 只查该集合，返回结果会说明
没有排除集合外更新或冲突的记录。明确读取私密资料时，扫描范围内其他记录缺失密钥
也会报错，不假装完整返回；现有历史快照完整性要求不放宽。

两个库接口可通过 `signal` 传入真实 `AbortSignal`（取消信号），不接受 JSON 信号、
执行程序或身份覆盖。停止等待不等于撤回已进入完成阶段的事务。若保存完成后权限
失效，错误只附带 `completedAvailability` 的证据 ID 与提交，不返回清单正文；原有
已提交取消信息仍保留。结果不明时先查当前记录及历史，不自动重试。没有数据库、
数据迁移或必填配置变化。
