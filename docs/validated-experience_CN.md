# 经验验证与技能导出

开发中功能：目前提供库接口、命令行和明确调用的 MCP/Harness 工具，尚不是网页完整流程，也不代表已经证明
真实 Agent 的效果。此流程不调用模型或外部服务。

执行记录包含任务类别 `family`、任务标识 `taskId`、执行标识 `runId`、场景
`context`、步骤 `actions`、观察结果 `observedResult`、结果状态 `outcome`
（`success` / `failure` / `partial`）及限制 `limitations`。它们是调用方报告的
观察，**不是已经独立证实的事实**。记录按现有权限、分类、加密和审计要求保存为
不可修改的原始证据；修正观察应新增证据，不能改写旧记录。

```sh
amem experience capture --root ./vault --file trace.json --scope project
amem experience prepare --root ./vault --file proposal.json
amem experience export ev-0123456789ab --root ./vault --confirm
```

提案文件需要 `traceIds`、小写连字符技能名 `name`、说明适用情况的 `description`、
流程 `procedure`、使用条件 `conditions` 和限制 `limitations`。
提案是有效期 24 小时的本地签名文件，不是已批准知识。单次经验可以生成提案，
但不能通过验证后导出。不能混合不同的非公开范围，不能降低来源的敏感等级；
可用 `sensitivity` 主动提高等级。

## 验证由可信宿主程序执行

库方法 `experienceValidate(plan, suite, runner, options)` 的 `runner` 是宿主提供的
可信程序，而不是 Agent 指定的脚本路径。命令行不接受执行器模块，不允许提交一份
预填“全部通过”的结果代替执行。宿主需要用有意义的独立任务实际检验这份流程，
如结果包含新的私密信息还需要正确分类。这里没有操作系统隔离，也没有自动秘密检测。

验证集 `suite` 包含名称和 `cases`；每个用例包含 `id`、独立的 `taskId`、类别
`category`、输入 `input` 及检查项列表 `criteria`。要求如下：

- 至少两个不同任务的成功来源；配置的 `minimumProcedureEvidence` 更高时按更高值。
  同一任务反复执行不能凑数。
- 至少两个未用于来源的迁移任务、一个原有行为保持用例、一个安全用例。
  类别分别为 `transfer`、`retention`、`safety`；所有用例任务互不重复且不在来源中。
- 验证程序接收 `{ plan, test, signal }`，返回 `observed` 和 `checks`；每个声明的
  检查项必须恰好返回一次 `{ criterion, passed }`。
- 必须全部通过才能导出。异常或无效结果记录为失败，不保存异常中的秘密信息。
  在提交准备完成前取消或超时，不创建新报告；若提交已经准备完成，按现有原子
  提交规则先完成提交，取消错误中会列出已完成的提交。

程序收到的提案和用例是独立副本。必须实际运行相应流程并与独立的预期结果比较，
不能固定返回“通过”。产品检查的是对应关系、完整性与任务覆盖，**不能判断验证
程序是否诚实、检查是否有意义，更不能因此证明所有场景有效**。

串行执行 4–32 个用例，每个 1–16 个检查项。默认总时限 30 秒，可设置
`timeoutMs` 为 100–120,000 毫秒；支持 `signal` 取消。可信程序应响应取消并自行
停止外部操作，不能把此机制当作任意代码的安全隔离。

验证报告按同一分类保存为不可修改的证据，关联具体流程、来源版本、用例和观察。
保存前及导出时重新检查来源、配置、租户、权限、私密选择和密钥。配置改变需要
重新准备并验证。全部通过也不会自动批准正式记忆；原有手工批准的流程记忆，
不能替代此处的跨任务验证。

异步读取及释放锁之后，还会重新检查当前身份的租户和权限。如果提交已经开始并
完成，随后才发现过期或权限变化，错误会保留原错误类型，并用 `completedValidation`
给出已保存的证据 ID 与提交，不返回报告正文。应在当前权限下检查这条记录；
不能把这种错误当作“什么都没有保存”，也不要直接重复运行验证程序。

## 导出不是安装

`experienceExport(validationId, { confirm: true })` 返回 JSON，其中包含
`files['SKILL.md']` 和 `files['references/validation.md']`。命令行打印相同 JSON，
不会创建目录。由用户决定保存位置、审阅和是否安装；不自动运行、发布或授予权限。

命令行记录/准备需要读写权限，库验证还需要审阅权限，导出需要读与审阅权限及明确
确认。`sensitive` / `secret` 资料在准备、验证和导出时分别需要额外明确选择
`includeSensitive` / `includeSecret`，命令行为相应的连字符参数。

导出可能包含私密明文，复制后无法撤回。移除来源权限或密钥只能阻止**新的导出**。
测试资料通过，只能证明所测用例；生产使用前还需要单独评估真实任务效果。

## MCP 与 DeepSeek Harness

| 工具 | 输入 | 当前权限 |
| --- | --- | --- |
| `memory_experience_capture` | `{trace, scope?, sensitivity?}` | 写入 |
| `memory_experience_prepare` | `{proposal}`，包含上文提案字段 | 读取与写入 |
| `memory_experience_export` | `{validationId, confirm:true, includeSensitive?, includeSecret?}` | 读取与审阅 |

记录工具只保存观察；准备工具只生成签名提案，不运行验证、不批准记忆。可信宿主
另外通过库接口执行验证。导出只返回文件字符串，不保存到 Agent 的文件系统，
不安装、不执行。

没有开放验证程序选择、安装或自动验证工具。输入不能覆盖服务端的资料库路径、
所属身份、权限，不能指定执行器或模块，不能提交预填的通过结果，也不能通过 JSON
传入取消信号。外层参数和提案／记录内部的未知字段都会被拒绝。取消继续由宿主的
调用及停止信号负责。

Harness 只注册具备相应组合权限的工具，记录默认范围与敏感等级沿用服务端配置。
MCP 沿用“工具可见、执行时检查权限”的方式：看到工具不代表有权调用。两者都
检查完整转义 JSON 的 9 MiB 上限，超出时拒绝，不截断技能说明。导出仍检查当前
来源、密钥、资料库所属身份、期限和私密资料选择；返回字符串不等于允许传播私密
资料，也不等于授予执行技能中操作的权限。
