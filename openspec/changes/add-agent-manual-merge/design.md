# Design

- Reuse the core snapshot and merge schemas with `signal` removed from tool arguments. Signals come only from the enclosing MCP request or Harness invocation/lifetime. Reject extra fields rather than silently ignoring requested authority or auto-apply.
- MCP lists both tools consistently with its existing server; execution checks current permissions. Harness advertises snapshot only to readers and merge preparation only to principals with both read and write. Approval still requires review authority in the core.
- Do not add an outer read lock: the core owns the settled read and checks time/cancellation after actual cleanup. Reuse the adapters' current cancellation/error and Harness disposal behavior.
- A shared helper bounds the complete pretty-printed JSON text including JSON escaping to 9 MiB, and checks a resubmittable original-plan approval envelope too. This leaves 1 MiB below the MCP SDK's default 10 MiB stdio buffer for protocol overhead; clients need not increase their buffer. Oversized output returns a content-too-large error, never a truncated comparison or partial plan. These are response bounds, not an operating-system memory sandbox.
- Preparation has no model call, canonical write or commit; existing proof-state initialization remains possible. Inputs and results can contain confidential plaintext. Signing is not encryption and copied content cannot be recalled.
- The existing explicit apply call is approval, not a new unattended action. The host/user must inspect the complete original plan and authorize it; tool descriptions and documentation state this. No new combined prepare/apply option.
