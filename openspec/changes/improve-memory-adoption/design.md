# Phase-one implementation

## Workflow
Client setup is a deterministic preview/apply/verify/remove workflow. Automatic context uses authorized approved knowledge as reference data. Optional completed-turn capture records evidence or candidates only. User corrections create immutable evidence before a signed repair plan; plan previews show the actual canonical before/after content and propagated restrictions, and apply still requires separate review authority.

Ordinary MCP/tool access remains available. Host automation is opt-in and uses the supported installed Harness prompt/session interfaces; unsupported hosts are not advertised as automatic. Secret provider credentials and encryption keys remain process-owned and are never written into generated client configuration.

## Boundaries
- Read-only recall, preview and explanation cannot change canonical knowledge. Recall includes ordinary memory and authorized active Wiki, complete citations, conditions and uncertainty within a bounded text budget.
- Previews verify signature, input/config versions and authority before exposing old or proposed content. All affected/dependent pages are explicit; hidden records do not enter counts, messages or model prompts.
- Corrections preserve the user's words, current source provenance and old conditions. A stale target revision cannot silently redirect a correction. Planning failure can leave captured evidence; success is never represented as an approved write.
- Automatic capture must stop when disabled, ignore aborted/error turns and remain idempotent on repeated event delivery. Plugin disposal cancels and awaits only owned work.
- Previewed client configuration revisions must still match at apply/removal. Existing unrelated entries and changed managed entries are preserved; removal refuses uncertain ownership.
- No vendor performance claim becomes a product acceptance result. Fixture protocol success, mechanical checks and human semantic assessment are reported separately. Live calls have explicit bounded budgets; missing usage/cost stays unavailable rather than zero.

## Delivery and verification
Keep implementation commits independently attributable. Test callback cancellation, stale revisions, forbidden scope/sensitivity, repeated events, configuration drift and rollback. Run retained gates with both Git defaults, Node 20.0.0 installed artifact checks and a real browser interaction for changed review UI. Review committed candidates with isolated read-only agents, using the OCR delegate file/rule inventory to account for changed files. Document checks unavailable in this environment rather than treating them as success.
