# Design

Use immutable Git object reads, not checkout, another worktree or a second search index. Accept only a full 40/64-character lowercase hash resolving to a commit in current HEAD ancestry. Require matching vault/tenant identities in the historical configuration and no pending transactions or dirty managed config/Wiki/evidence. Existing operation cancellation and Git deadlines apply. The existing writer lock covers current authorization and all historical reads; detect external HEAD or managed-file changes before returning.

Resolve explicitly requested keys through the current eligible Wiki graph. Follow historical page links/dependencies, immutable evidence and rule revisions, requiring every historical dependency to remain currently accessible. Check both envelope and logical metadata with current encryption policy. Confidential pages/sources require explicit opt-in in addition to principal permission; key erasure cannot be reversed. Reuse Wiki validation on the reconstructed bounded historical graph. Reject unavailable, revoked, expired or currently ineffective dependencies, including historical dependencies no longer mentioned by the current root page. Return all required pages or fail, never silently drop context.

Limit requested keys to 25, dependency pages to 50, stored records to 200, individual blobs to 10 MB and aggregate stored bytes to 20 MB. Sources/rules validate provenance but output only their identities/hashes/revisions, not raw source text, PDF bytes or rule instructions. Preserve page metadata, conditions, conflicts, uncertainty and actual revision; separately report current revision. A historical view is not current advice, fact-effective history or independent evidence. Every read reapplies current checks; a previously copied result cannot be recalled or used as a new authorization token.

No persistent snapshot entities, schema/config migrations, model requests or canonical mutations are needed. Keep source and compiled knowledge separate. Test version changes, dependency cycles/limits, confidential opt-in, parent cancellation, lock ordering, source/rule/key loss, stale authority, dirty state and exact installed Node20/22 consumers; independently review committed candidates.
