# Design

The existing `wikiSnapshot` accepts either the unchanged `WikiSnapshotOptions` with `commit`, or new `WikiDatedSnapshotOptions` with `at`. Strict schemas reject both/neither, extra host fields and duplicate keys. Dates require timezone-bearing valid ISO timestamps with millisecond precision and normalize to UTC.

The existing settled read owns both resolution and page reading; no outer adapter lock delays post-cleanup lifecycle checks. Git safety checks (including replacement/graft/promisor behavior), current configuration and clean state apply before history traversal. Query up to 2001 local first-parent commit entries with explicit hash/time format and notes/signatures/display additions disabled. Examine the first 2000, in ancestry order, selecting the first whose committer time is at or before `at`. No `--until` shortcut: non-monotonic parent clocks must not hide an eligible ancestor. If none matches and more history remains, fail with a size error; otherwise fail unavailable. No fallback to a different snapshot when a requested page is unavailable.

Result `commit` identifies the selected version, `authorityHead` current authority, and optional `selection` records Git-committer-time kind, normalized requested/committed time, first-parent traversal and examined count. Explicit hash reads retain their prior shape. Ties choose the first ancestry entry; future dates select the first eligible existing entry, never predict. Git timestamps can be rewritten/backdated and are not evidence of historical truth, import time or agent knowledge. Merge side-parent commits are not independently selected; a merge's tree becomes available when its first-parent entry matches.

Current tenant, scope, sensitivity, confidential opt-in, key availability, provenance, revocation and historical/current lifecycle checks remain in force, including after real asynchronous lock cleanup. Existing Git deadlines and invocation cancellation remain; no new overall timeout, OS memory sandbox or old-key restoration. Exports can contain confidential plaintext and cannot be recalled after copying. Existing MCP/Harness 9 MiB and HTTP response limits remain. No schema/config/database migration.
